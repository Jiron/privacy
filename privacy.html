3. General principles

First and foremost, we process personal data that you provide to us or that we collect when operating our website. We may also receive personal data about you from third parties. These may be the following categories:

4. Individual data processing operations

4.1 Providing the website and creating log files

What information do we receive and how do we use it?

By visiting https://www.jiron.dev, https://www.discorddevtools.xyz, https://api.discorddevtools.xyz, https://www.interlink.gg, https://calls.interlink.gg, https://jiron.github.io/privacy/ (and any subpage or other missing subdomains of any of those domains), or by using the InterLink Discord Activity, certain data is automatically stored on our servers or on servers of services and products that we obtain and / or have installed, for purposes of system administration, for statistical or backup purposes or for tracking purposes. These are:

  • the name of your Internet service provider;
  • Your IP address (in some circumstances);
  • the version of your browser software;
  • the operating system of the computer with which the URL is accessed;
  • the date and time of access;
  • the web page from which you are visiting URL;
  • the search words you used to find the URL.

How these log files are written and what exactly they contain

Our own servers for the DiscordDevTools API (https://api.discorddevtools.xyz) and the Welcome Image Generator write one entry per request into a plain text file. A new file is started every day and the files are grouped into one folder per month. Each entry contains:

  • the date and time of the request, to the millisecond;
  • your IP address, and separately the address of the proxy the request arrived through (this is normally Cloudflare), so that a forged address can be recognised;
  • the HTTP method, the full requested URL including all query parameters you passed, the response status code, the response size and how long the request took;
  • the host name you addressed, your browser's user-agent string, and the referring page;
  • a randomly generated request identifier, used only to match up lines belonging to the same request;
  • on the Welcome Image Generator, additionally the request headers and up to the first 2048 bytes of the request body.

Fields that typically carry credentials are never written to these files. Authorization headers, cookies, API keys and any body field named like a password, secret, token or session are replaced with [redacted] before the entry is written. The log folder and files are readable only by the account that runs the server.

Requests that are malformed enough that they never reach the application are logged too, with the address they came from, because that is the shape most scanner traffic takes.

Why may we process this data?

The log files are stored in order to guarantee the functionality of our services, to investigate faults, to recognise and defend against attacks and abuse, and to ensure the security of our information technology systems. This is our legitimate interest (Art. 6(1)(f) GDPR).

Please note that, unlike what a shorter statement might suggest, an IP address in combination with a timestamp can under some circumstances be traced back to you, and we therefore treat these log files as personal data throughout.

How long are they kept and how can you prevent data collection?

Log entries are kept for up to 12 months from the day they are written and the daily file is then deleted. Writing them is mandatory for the secure operation of our services, so you have no possibility to object to the logging as such. You can of course limit what ends up in the URL line: everything you pass as a query parameter to our API is written to the log, so do not pass anything there that you would not want stored (see also section 4.9).

4.10 InterLink (Discord bot, web call panel and Discord Activity)

InterLink is a free Discord bot that connects the voice channels of two different Discord servers so that their members can talk to each other, together with a web call panel (https://calls.interlink.gg) and a Discord Activity that show who is in the call. The following describes what InterLink processes. The bot's own terms, which you accept before you can set it up, are available at https://calls.interlink.gg/terms and at the same address on our other InterLink domains; where they and this policy differ, section 6 applies.

a. What we store in our database

We store the following in our database (see section 4.11 for where that database lives):

  • Per user: your Discord user ID, whether you have accepted the terms of service and privacy policy, and the on/off state of each of your settings (voice transfer, show profile picture, show display name, show username). A record is created the first time the bot has to look you up.
  • Per Discord server: the server's ID, which other servers it has blocked, the channel chosen for messages, and whether calls, the randomizer and the phone book listing are enabled.

We do not store your username, display name or profile picture in our database. Those are fetched from Discord while a call is running and are kept only in the memory of the running server for as long as the call lasts.

b. Voice and the "Allow Voice Transfer" setting

This setting is off by default. It only becomes active when you switch it on yourself using the bot's /settings command, and switching it off again withdraws your consent for the future.

While it is on, and while you are in a voice channel that is part of a call, our bot receives the audio you send to that voice channel, decodes it, mixes it with the audio of the other participants and plays it into the connected voice channel on the other Discord server. That is what makes the call work. The audio is handled in memory for the duration of the call and is not written to disk; when the call ends, it is gone.

We also receive and pass on your speaking state (whether you are currently talking, shown as a green ring on the call panel) and your mute and deafen state.

Recording: we reserve the right to record the mixed audio output of participants who have this setting enabled, solely so that a moderator can check a report of abuse. Any such recording is deleted at the latest 24 hours after the end of the call and is not backed up, and it is only ever looked at in response to a report, or where we are legally required to or are directed to by Discord. If you do not want to be recorded under any circumstances, do not enable this setting – the rest of the bot works without it.

Please also be aware that anyone else in the call can hear you, and that we cannot prevent a participant from recording a call on their own device.

c. The display settings

"Allow To Display Profile Picture", "Allow To Display Display Name" and "Allow To Display Username" are likewise off by default. Only if you switch one on do we retrieve that item from Discord and show it to the other participants on the call panel and in the Activity; otherwise a placeholder is shown instead. These items are shown live and are not stored by us. Please note that these settings govern your name and picture on the call panel only – see d. below for what is shown about you regardless of them.

d. What the other server and its members can see

The point of InterLink is to connect two different Discord servers, so some data necessarily crosses from one to the other. Please read this carefully, because the settings in b. and c. do not cover all of it:

  • When you place a call with /call, your Discord display name is posted into a text channel of the server you are calling, together with the name and ID of the server you are calling from, so that the people there can decide whether to accept. This happens regardless of the "Allow To Display Display Name" setting, which governs the call panel and not the call notification. If you do not want your display name shown to a server you are calling, ask someone else on your server to place the call.
  • Your Discord user ID is visible to everyone who opens the call panel or the Activity for a call you are in, including members of the other server, because it is used to identify your tile on the page. The display settings in c. control your name and picture; they do not hide your user ID, and a Discord user ID can be used to look an account up.
  • The names and IDs of both servers and your speaking, mute and deafen state are shown to everyone in the call.
  • Your audio, if you have enabled voice transfer, is heard by everyone in the connected voice channel on the other server.

Separately, the /phonebook command shows a list of the servers that can be called, with each server's name and ID, to anyone who runs it in any server the bot is in. A server is listed by default. Anyone who administers a server can take it off that list through the bot's settings, and can also block individual servers or switch off calls entirely.

e. Logging in to the web call panel and the Activity

To open the call panel for a server, you log in with Discord (OAuth2). Discord asks you to authorise this and then sends us an access token and a refresh token, which we place in your browser as HttpOnly cookies (see section 3.9) and use to ask Discord who you are, so that we can check that you are actually in the call you are trying to view. We request only the "identify" and "guilds" permissions, and we do not receive your Discord password. During this, we process your Discord user ID, and the ID and name of the server and the voice channel concerned.

The Discord Activity works the same way, except that Discord itself performs the authorisation inside your Discord client and the resulting token is passed on to the page in the address of the embedded view. We do not store these tokens on our servers; they live in your browser session and expire.
